## 二、交付了什麼

### 白板（人類端）

challenge 建立與切換、Fact / Assumption 依 section 分區檢視、note 與 command_result 送入、
六種 mutation（add / replace / remove / promote / demote / move）、`mark_tried`、
template 切換、Query。等同 `ctfmem` 的操作面。

### Agent 面板

啟動 `ctfmem agent run`（normal 與 YOLO）、即時狀態、停止、子行程輸出。
可切換成「假 agent」重播真實錄製，零成本零金鑰。

### 抽籤拉霸

從 Guessing 目錄抽一個技術，轉盤動畫落定後，讓你把它寫成**這一題的具體假設**存進 Assumption，
來源記在 `tags`（`guessing` + 技術 ID）。

## 三、三個架構決定與理由

### 1. 同源代理，而不是「靜態頁 + 幫 Core 開 CORS」

`memory_core/api.py` 沒有 CORS middleware。要讓靜態頁直接打 Core，就得改那個**權威服務**去遷就
一個 client 的部署形狀，並在擁有全部寫入權的 process 上掛一份寬鬆的來源政策。改成同源之後，
這個問題整個消失。

### 2. Agent 用 spawn 子行程，而不是在 server 裡跑 loop

四個機制上的理由，都不是風格問題：

- `AgentLoop.run_yolo` 會 `signal.signal(SIGINT, ...)`。在 uvicorn 主執行緒等於搶走 Ctrl-C；
  丟工作執行緒則會拋 `ValueError` 被吞掉，等於沒裝。
- `agent-status.json` 記的是 `os.getpid()`，只有在「執行者就是自己的 process」時才有意義。
- `agent_bridge/runtime.py` 自己的 docstring 就說這些是 client-owned 的跨 process 控制檔。
- 一次執行是分鐘等級，HTTP request 不可能同步等它。

**副作用正是要的**：終端機的 `ctfmem agent status` 完整看得到瀏覽器啟動的執行（已實測），
反之亦然。行為零漂移不是靠紀律，是因為只有一份實作。

### 3. 代理層不驗證任何 request body

缺 `reason`、revision 給字串、operation 不認得——全部由 Memory Core 用它自己的話回答。
一個會去驗證凍結 schema 的代理，等於在合約上長出第二個權威，而且同一種錯誤會有兩種狀態碼
與兩種信封。

## 四、邊界（沒碰什麼）

- `spec/` 與 `memory_core/` 零改動：`git diff --name-only main...HEAD -- spec memory_core` 為空。
- 零新執行期依賴。前端無 build step、無 npm、無 CDN、無外部請求（有測試釘住）。
- 頁面不保存權威狀態：不配 ID、不算 diff、不留第二份記憶。重新整理不會失去任何重要的東西。
- `actor` 一律來自 server 設定，頁面宣稱什麼都無效（有測試釘住）。
- Core 的錯誤原封轉發；代理自己產生的錯誤用**結構上可區分**的 `webui_error` 信封，
  並避開合約錯誤表已經用掉的狀態碼（`core_unreachable` 用 503 而非 502，因為 502 語意相反）。
- 新增路由一律掛 `/api/local/*`；`/api/v1/*` 由既有測試斷言**恰好等於** `spec/openapi.yaml`。

## 五、併發

每次寫入都帶 `expected_revision`，但**來源依控制項而異**，這是刻意的：

- **Override / Reclassify / 拉霸**：revision 在你開始填表時捕獲，不在送出時重抓。送出時重抓
  等於默默吞掉你打字期間別人的變更。白板中途移動 → 送出鍵鎖住並提供「重新組合」。
- **Guessing 勾選**：用點擊當下畫面上的 revision。checkbox 沒有組合視窗，沒有東西會過期。

409 一律不自動重試，重讀後把「你組合的是 rM、現在是 rN」攤開。判斷條件只認
`error.code === "revision_conflict"`——因為 **409 是共用的**，`challenge_exists` 也是 409。

值得一提的兩條測試：

- **路由表測試從 `spec/openapi.yaml` 推導期望值**，不是內省 `memory_core`。所以它追的是合約，
  不是別人的實作；這個 server 一旦長出合約沒有的端點就會紅。
- **反漂移測試**把每一組要丟給子行程的參數餵進 CLI 自己的 parser，並且**真的把進入點 spawn 起來**
  跑一次。前者防旗標改名，後者防「跑起來其實什麼都沒做」。

### 涵蓋不到的（誠實列出）

- **零 JavaScript 測試**（刻意）。頁面靠人工驗收，清單寫在 `docs/human-webui.md`。
- **spawn 的端到端無法自動化**：子行程要走真 socket 才連得到 Memory Core，而
  `tests/conftest.py` 的離線守衛擋掉 connect。這段用注入假 spawn 的契約測試 + `--fake-agent`
  人工驗收，文件裡寫明而不是假裝有覆蓋。
